Independent Case Study

Adaptive Menu UI

VALORANT User Research & PRD Case Study — Hamilton Shea, July 2026

After talking to 6 VALORANT players, I designed a responsive Shop and Settings concept for 5:4 and 4:3 stretched resolutions. It keeps the menus usable and leaves the actual game alone.

Where This Started

The Player Need

Players using 5:4 or 4:3 stretched resolutions need Shop and Settings controls to stay visible and clickable. They should not have to change the gameplay setup they prefer just to use the client.

Why I Care

I use 5:4 stretched because it feels easier than 16:9. Matches feel fine, but the menu gets squished and Quests can cover Shop. Before a game I should be focused on the match, not fighting the client.

Evidence boundary: the blocked Shop click is my own repeated observation. The interviews and public posts support the broader stretched-resolution problem, not that exact overlap.

Scope: out-of-match menus and Settings only. No changes to the HUD, crosshair, minimap, FOV, hitboxes, player models, aiming, or competitive integrity.

What Six Players Told Me

I spoke with 6 VALORANT players and wrote down their opinions about navigation, UI changes, stretched resolution, and what they would actually want fixed. I compared that feedback with my own 5:4 use and two public Reddit discussions from different UI updates.

EvidenceWhat Stood OutWhat It Changed
6 player interviews They did not ask for a full redesign. They mostly wanted navigation to stop getting worse or harder to understand. Keep the visual style familiar and fix the layout behavior.
My own 5:4 use Matches feel normal, but the client can block Shop before I even queue. Treat blocked Shop access as the highest-severity problem and leave gameplay alone.
Public Reddit posts Players complained about stretched Shop readability in 2024. A separate 2026 thread criticized extra clicks, reduced clarity, and oversized layouts. Use them as outside signals that the issue did not start with me.

Why This Direction

A one-screen patch would be faster. I still rejected it because it only fixes today's version of the problem. The next event banner, quest panel, purchase flow, or Settings update could create the same conflict somewhere else. Shared safe-frame rules cost more upfront, but they stop the same layout problem from being patched over and over.

OptionImpactEffortWhy I Considered It
Patch only the blocked Shop state Medium Low Fast, but the same conflict can return on another screen or update.
Manual UI scale control Medium Low Helpful fallback, but puts setup work on the player and may not prevent overlap.
Fixed native-ratio menu canvas High Medium Predictable and safe, but can feel visually disconnected from the chosen display mode.
Responsive menu breakpoints + safe frame High High Addresses the system behavior and supports future out-of-match screens. (Selected)

The version I would test first

What I Would Touch

  • Shop and Settings reflow at 5:4 and 4:3 breakpoints
  • Critical actions remain inside a protected safe UI frame
  • Quests can collapse to one icon when space becomes limited
  • One Adaptive Menu UI row exposes optional scale and safe-area controls

What I Leave Alone

  • In-match HUD, minimap, crosshair, ability icons, or kill feed
  • FOV, hitboxes, player models, sensitivity, or aiming behavior
  • VALORANT's core visual identity or every client screen
  • The native-resolution experience unless adaptation is needed

MVP Scope

IDBuild RuleHow I Would Check It
R1Detect viewport and load the matching menu profile.Updates after startup or a confirmed display change.
R2Keep critical Shop and Settings actions inside a safe frame.Shop, back, close, confirm, cancel, and Apply stay clickable.
R3Reflow menus at 5:4 and 4:3 breakpoints.Secondary panels move, collapse, or stack without blocking actions.
R4Use one expandable Adaptive Menu UI row in Video Settings.Collapsed by default; no new lobby button.
R5Preview and revert unconfirmed display changes.Last known-good layout returns after 15 seconds.
R6Leave all in-match UI and gameplay untouched.No HUD, FOV, input, model, or competitive change.

Where I Could Be Wrong

I like the idea, but I would drop it if the evidence says it is the wrong fix.

EvidenceDecision
The overlap only occurs in one temporary event state.Ship a targeted Shop fix instead of a shared responsive system.
Responsive reflow creates unacceptable performance or input risk.Use a fixed native-ratio menu canvas and safe-area control as the MVP.
Usability testing does not improve task completion or reduces clarity.Kill the concept or narrow it to the single highest-severity screen.
Native-resolution users regress or any in-match behavior changes.Do not release until the regression is removed.

What I Would Do Next
